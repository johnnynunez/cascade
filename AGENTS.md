# AGENTS.md

This file provides repository guidance for AI coding agents.

CASCADE (repo: `github.com/johnnynunez/cascade`; Python package/import path and CLI entry points are unchanged — see README's "Naming note") is LLM-orchestrated tabletop manipulation, robot- and device-agnostic by design: 10 arm profiles spanning 5/6/7 DoF over CAN, a Feetech serial bus, MuJoCo and Isaac, with backend capabilities selected explicitly. Generic models can resolve available accelerators; the Spark presenter requires CUDA. The reference rig is a Seeed reBot DevArm B601 (RobStride) driven from an NVIDIA DGX Spark — treat that as *one* configuration, not the subject. Read `README.md` (user-facing overview, quick start, safety notes) and `docs/ARCHITECTURE.md` (module map, design decisions) first — this file covers what they don't, and flags where they are stale (see "Doc status" at the bottom).

## Environment & commands

On the reference rig there is no bare `python` and `python3` has no pytest, so everything runs through a uv venv. The interpreter path is machine-specific — derive it, never hardcode it:

```bash
source "$(cd .. && pwd)"/.demo/bin/activate    # reference rig layout
# or, from a fresh clone anywhere:
uv venv && uv pip install -e '.[dev,kinematics]' && source .venv/bin/activate

python -m pytest tests/ -q                             # full suite; source-bound results: docs/PROJECT_STATUS_20261001.md
python -m pytest tests/test_safety.py::test_velocity_cap -q    # single test
python -m pytest tests/ -m hardware -q                 # live-rig tests (L515 + can0, read-only)

# offline wiring check: mock camera + mock arm + scripted LLM, no hardware, no GPU
python -m cascade.apps.demo --task "pick and place pink object"
python -m cascade.apps.demo --interactive --no-view --no-serve   # REPL, no GUI/dashboard

# same cascade on the 5-DoF SO-101. `mock_small` is the matching scene: the
# default `mock` box is 7 cm across and a 55 mm jaw correctly refuses it, so
# `--camera mock` on this arm only ever exercises the rejection path.
python -m cascade.apps.demo --arm so101_mock --camera mock_small --task "pick and place the red object"
```

- Tests insert their checkout’s `src/` through `tests/conftest.py`. For apps and diagnostics in another worktree, set `PYTHONPATH` to that worktree’s absolute `src/` path: a shared editable venv may still point at the original checkout. Verify imported module paths when binding a run to a source revision.
- `addopts = "-m 'not hardware'"` in pyproject applies even to explicitly named files: `pytest tests/test_hardware_smoke.py` runs **zero tests silently** — you must add `-m hardware`.
- Pinocchio-dependent tests skip via `needs_pin` from conftest when `pin` or the RS URDF under `assets/` is missing. The SO-101 equivalent is `needs_pin_so101` — its URDF *is* vendored, so in practice only `pin` gates it. Pinocchio is not really optional: FK/IK back the safety layer, so a minimal install is base deps + `kinematics`.
- CI is a 3-OS matrix (`ubuntu-latest`, `ubuntu-24.04-arm`, `macos-latest`; Python 3.12) running the source-defined extras (including sim-warp, grasping and grasp-safety), kitchen-source admission and pytest, plus a `minimal-install` job that asserts torch/ultralytics/mujoco/pyserial/openai are ABSENT and still runs a full SO-101 mock episode. The aarch64 leg is the Jetson architecture; the macOS leg is the MPS path. The separate booth-UI job also validates browser assets and extensions; `.github/workflows/ci.yml` is authoritative.
- MuJoCo tests need fetched assets as well as the package: `python scripts/fetch_robot_assets.py so101` (~17 MB, gitignored). Without them `tests/test_mujoco_arm.py` skips its physics half with a message naming the command; the profile/name-mapping half always runs.
- `scripts/setup_env.sh` defaults its interpreter to a stale absolute path from the original dev box — pass `PY=<interpreter>`. The venv has no `pip` module; use `uv pip`.

## Architecture

`docs/ARCHITECTURE.md` has the module map and data-flow diagram. The load-bearing facts beyond it:

**Composition root.** `apps/demo.py:build_runtime()` is the single place everything is wired: kinematics → LazyArm → SafetyHarness/SafeArm → ArmRig → CameraRig of CameraStreams → LockedDetector → WorldWatcher → BeliefStore/EpisodicMemory → TraceLogger → SkillRuntime → optional StreamServer/RigViewer. The demo CLI, `apps/mcp_server.py`, and `scripts/dashboard_runner.py` all call it; tear down with `shutdown_runtime()`. Detector selection: only the FIRST/manipulation camera's profile can override the global `detector:` in `configs/demo.yaml` — one shared `LockedDetector` serves the whole rig, and `detector:` blocks on non-primary camera profiles are silently ignored (the mock camera pins `type: mock` so offline runs never import ultralytics). The first camera in any `--cameras`/`CASCADE_CAMERAS` list is the manipulation camera; the rest only stream/fuse. A camera fuses 3D beliefs only if its profile has an `extrinsics:` block (or `fuse_beliefs: true`).

**The arm rig (`control/arm_rig.py`, added 2026-08-28).** `ArmRig` is the deliberate twin of `CameraRig`: N named arms, first = manipulation arm, `get(None)` returns the primary. `--arms a,b` (or `arms=[...]` in `load_demo_config`) builds it; `--arm a` is the one-arm case and is byte-identical to the pre-rig behaviour (pinned by `tests/test_arm_rig.py`). `runtime.arm` still binds to the primary `SafeArm`, so the skill layer's 56 `self.arm` uses were untouched; the rig hangs off `runtime.arm_rig`.

Each arm gets its OWN `SafetyHarness`. That is the whole point: every limit in `SafetyLimits` (workspace box, velocity cap, joint margins, table height) is a property of a particular robot on a particular table, so merging every arm's `overrides:` into one global config would let the LAST profile loaded define the envelope for BOTH. `load_demo_config` therefore applies only the PRIMARY arm's overrides at the top level and stores each arm's own view under `cfg.arms[i].resolved`, which is what `_build_arm` hands to that arm's harness. The `occupancy` map is the one shared object (it describes the world, not the robot, and the WorldWatcher only refreshes one — a per-arm copy would age out and silently stop gating).

**Addressing an arm from a skill call.** Every skill in `_MOTION_SKILLS` takes an optional `arm="<name>"`; `list_arms` reports the names. It is resolved in `SkillRuntime.execute()` — the single choke point — which pops `arm` from the kwargs and rebinds `self.arm` for exactly that call, so **no skill signature changed** (all 56 `self.arm` uses still read the right robot). `SkillRuntime.arm` is therefore a property over a thread-local override: the MCP server answers stop frames on a reader thread while a skill runs on a worker, and a plain attribute would let one thread's arm selection leak into another's. The override is restored in a `finally`, so a failed motion on the second arm cannot leave later skills pointed at it. The `arm` schema entry is INJECTED over `_MOTION_SKILLS` at the bottom of `runtime.py` rather than hand-written into 15 schemas — dispatch already derives the set from `_MOTION_SKILLS`, and a hand-copied list would drift the moment a motion skill is added. An unknown name is a `SkillError` (`{"ok": false}`), never a silent fallback to the primary: on a shared table that would be a collision, not a wrong answer.

**Inter-arm collision (`safety/harness.py`, added 2026-08-28).** Solved for the geometry, not for meshes. An arm profile may declare `base_pose: [x,y,z,r,p,y]` — where that robot is bolted, in a SHARED TABLE FRAME (`types.pose_to_transform`, URDF `<origin rpy=...>` convention). That is the enabling piece: every other position in this codebase is in the ROBOT BASE frame, so two arms' links are not comparable until both are lifted into one frame. RPent (PR #98) solves the same problem by declaring one arm's base canonical; a table frame is the same idea without privileging a robot. With `base_pose` on two arms, `_wire_neighbors` (demo.py) gives each harness a *callable* per neighbour; `approve()` then gates every sampled waypoint on measured link distance, and `vet_pose()` applies the same gate pre-motion so a doomed grasp candidate loses at ranking time. (`safety.neighbor_clearance_m` defaults to 0.05 m — see below for why that number, and why it used to be 0.10.)

Three properties that are load-bearing and easy to break: (1) the distance is SEGMENT-to-segment on link centrelines (`safety/geometry.py`, clamped-parameter closed form, vectorised), NOT point-to-point on joint origins — the point version had a real blind spot: measured over 4000 random pose pairs it overestimates clearance by up to 3.3 cm, e.g. reporting 6.6 cm for links that are 3.3 cm apart, which a 5 cm gate then accepts. Link *shape* is a per-segment capsule radius (`safety.link_radii_m`, so101.yaml: measured on the Menagerie SO-101 collision geometry, up to 9 cm) subtracted from the centreline distance, so `neighbor_clearance_m` (0.02 m on the dual profiles: two 50 Hz ticks at the velocity cap) is a margin between link SURFACES; from inside the margin only waypoints that do not close in are approved (retreat stays open). MEASURED against MuJoCo with both arms in one world (`tests/test_multi_arm_physics.py`, 2026-10-07, ROADMAP #8): that surface clearance is a lower bound on the mesh distance — every approved pose pair is ≥ the margin apart in physics — whereas the earlier centreline gate at 0.05 m approved 12 of 2000 random pairs whose meshes overlapped. A radii list that does not match the chain fails closed (construction error for the arm's own, blocked motion for a neighbour's); (2) an unreadable neighbour degrades to SKIP, never to "blocked" (this neighbor policy is not the payload-map policy) — the only such case here is a standby LazyArm, because reading its joints would power the motors from inside a safety check, which is also why the neighbour is a callable and not an arm object; (3) with no `base_pose` and no neighbours the check returns before touching kinematics, so a single-arm rig pays nothing. Cost when it does run: 77 µs per waypoint, 0.4% of the 50 Hz budget. The shipped `so101_left`/`so101_right` sit 0.44 m apart and deliberately SHARE workspace — at 0.60 m they never come closer than 0.218 m and the check would be decorative. `keep_out` is no longer the separation mechanism for these profiles.

**Camera calibration (`perception/calibration.py` + `scripts/calibrate_camera.py`, added 2026-08-28).** `Extrinsics` consumed a `T_cam2base` that nothing in-repo produced. Now `fit_extrinsic()` recovers it by Kabsch from point correspondences — the arm is its own target: FK gives the base-frame point exactly, depth gives the camera-frame one (RPent PR #29 does the same, detecting the jaw by toggling the gripper). **A rigid fit never fails, it only fails quietly**, so the result carries `rmse_m` AND a `spread_m` degeneracy check, and `.acceptable` gates both; `load_extrinsic` refuses a rejected record by default. The traps, both measured on this arm: coplanar samples give a **0 mm residual on a wrong transform** (only `spread_m` catches it), and `MIN_SPREAD_M` is 0.015 because the SO-101's reachable top-down band is only ~0.06 m tall — 0.03 would reject every real calibration. `_collect` tries a radial tool yaw *and* home's orientation per target, because the fixed orientation alone solved 13/80 poses all at y=0 (a degenerate cloud); trying both gives 44/80 and recovers a known extrinsic to 0.31 mm / 0.094°. `--self-test` exercises all of it offline and moves nothing.

**Skill system (the main extension point).** No registry: `SkillRuntime.execute()` in `src/cascade/skills/runtime.py` dispatches to `skill_<name>` methods by name, and `TOOL_SPECS` at the bottom of the same file is a hand-maintained list of JSON schemas. To add a skill: (1) write `skill_<name>()` returning a dict — raise `SkillError`/`SafetyViolation` for failures, never let other exceptions escape by design (`execute()` converts everything to `{"ok": false, ...}`); (2) add a `TOOL_SPECS` entry — `tests/test_llm_and_library.py` asserts the mapping in BOTH directions (every spec has a `skill_` method, every `skill_*` method has a spec, every `_MOTION_SKILLS` name is real) and pins README's headline skill/tool counts to the derived numbers, so forgetting the entry or the README line fails the suite; (3) **if it moves the arm, add it to `_MOTION_SKILLS` (top of runtime.py)** — this is what pauses WorldWatcher belief fusion during motion AND what records the Vesta memory frame + verdict afterwards; forgetting it re-registers the held object at bogus mid-air positions and leaves the step out of `task_memory`. Since 2026-10-07 it is also what the advisory pre-motion plausibility critic interrogates (`agent/milestones.py::_PLAUSIBILITY_QUESTIONS` — give the new skill a question keyed on its TOOL_SPECS arg names, else it gets the generic one; the critic never refuses, so a missing question costs wording, not safety); (4) tracing (trace.jsonl + keyframes + narration) and MCP exposure are automatic — `execute()` is the single choke point, and `mcp_server.py` serves `TOOL_SPECS` minus `_EXCLUDED_TOOLS` plus `_EXTRA_TOOLS`, minus whatever the rig's capability matrix withholds (`apps/capabilities.py`: if the new skill cannot run without depth, measured heights, a second arm, the verifier or a sidecar, add a `TOOL_REQUIREMENTS` entry — a skill that merely degrades gets none; `tests/test_mcp_server.py` pins every key to a served tool); (5) optionally add a regex to `_RULES` in `agent/reflex.py` so the command runs LLM-free (rules are order-sensitive, first match wins, and they drive the real arm with zero LLM involvement — test against `tests/test_streaming_fastpath.py`). One schema source feeds all three consumers (OpenAI-compat, Anthropic, MCP) — a new skill needs zero per-backend work.

**Three-tier dispatch.** `AgentOrchestrator.run_task()` tries tier-1 reflex (regex grammar) then tier-2 experience (hashed-BoW cosine ≥ 0.9 AND wins > losses, persisted in `runs/experience.json`) before ever calling the LLM. Since 2026-10-07 tier 2 also holds **recipes** (`memory/recipes.py`, persisted one per line in `runs/recipes.jsonl`): a VERIFIED LLM-tier run stored with every `place_at` coordinate replaced by a `{"$target": {"query": "localize_object", "label", "offset_m"}}` query anchored on an object perceived before the first motion (drop-zone names and labels stay symbolic; an unanchorable coordinate refuses the recipe rather than storing a raw value). On a tier-2 hit `_try_fast_path` grounds every query through `runtime.execute("localize_object")` BEFORE the first motion and aborts to the LLM tier with zero motion if any query fails — there is no stored coordinate to fall back to; a replay outcome is recorded against the SYMBOLIC calls (`plan.calls`), never the grounded ones. The envelope's derived features (`DERIVED_FEATURES`) are measured by `skill_grasp_object` into the per-call `_call_measurements` scratchpad that `_execute_skill` owns; a skill that measures nothing gets `missing` counts, never defaults. The LLM loop ends only via a `task_done` tool call or `max_steps` (default 30); only the FIRST tool call per turn executes (extras get error results back — the OpenAI protocol requires a result per call id). Import the orchestrator as `from cascade.agent.orchestrator import AgentOrchestrator` — `agent/__init__.py` deliberately doesn't re-export it (circular import with `skills.runtime`).

**Motion safety path.** Skills use `SafeArm`; `SafeArm.raw` exposes explicit backend-specific operations. Motion enforces velocity, joint/workspace/table limits, stop generation and the configured perception/geometry gates. Hardware retains its 50 Hz default; Isaac uses 30 Hz nominal commands with the original complete 50 Hz edges and extra actual/subedges checked by `harness.approve()`. `approve()` retains escape rules; `vet_pose()` is the static counterpart. Isaac pacing, settling and RPC deadlines use the contracts in `docs/ISAAC_MOTION_CLOCK.md`. An ordinary stale non-payload map can be unavailable, but a known body-mask fault rejects and payload/recovery modes require fresh, correctly bound observed geometry. Their unknown-space and clearance rules cannot be described as a general skip-on-failure policy. Pending contact/release episodes also restrict gripper/motion commands. The observed-finger path adds a preflight before each close stage; it is not a continuous brake after a gripper command has been submitted. See `docs/NVBLOX_RELEASE_RETREAT.md` and `docs/observed-finger-closing.md`.

**Grasp pipeline.** `configs/demo.yaml` defaults `grasp.backend: graspgenx` — learned 6-DoF grasps from a ZMQ server (`scripts/serve_graspgenx.sh`, :5556). Optional profiles can fall back to analytic OBB and retry learned inference after cooldown. **The Spark presenter profile requires real GraspGen-X and fails visibly instead of substituting OBB**; startup probes actual diffusion inference. Candidates are stably quality-sorted before `GraspOutcomeMemory` re-ranking/z-nudging (persisted at `~/.cascade/grasp_memory.json`); the runtime explicitly preserves that resulting order through `select_grasp()`. Width, IK, harness and observed-scene vetoes remain mandatory. The observed path uses the shared full motion profile, including legacy complete edges, before motion. Direct selector callers retain quality ordering by default. Grasp IK is seeded from `home_q`, not the live pose, and re-homes before the pregrasp on purpose (elbow-down IK branches dip links below the table) — don't "optimize" either away.

**Config system.** `load_demo_config()` loads `configs/demo.yaml` and inserts whole profile dicts under `camera`/`cameras`/`arm`/`llm` — no deep merge between profiles, no env interpolation; the only substitution is `${repo}`/`${assets}` in strings. One exception (2026-07-20): `CASCADE_BOOTH=1` deep-merges `configs/booth.yaml` on top of demo.yaml (booth timing budgets; sets `booth_mode: true`) — `tests/test_config_booth.py` pins the merge. Adding a profile = dropping a YAML file in `configs/{cameras,arms,llm}/`; the `type:` key selects the backend class in the `make_camera`/`make_arm`/LLM factories. `Cfg` is an attr/dict hybrid: attribute access for required keys (raises), `.get()` for optional; the sanctioned runtime-override idiom is writing into `cfg._data` (see `mcp_server.py`). Paths derive from `config.py`'s location, so the package only works from a source checkout.

**Adding a camera/arm backend.** Subclass `CameraBase` (implement `open/close/has_depth/_grab`; `_grab` raises `CameraError` for retryable faults and must NOT set `frame_id` — the watcher dedupes on it) or `ArmBase` (six abstract methods), add a lazy-import branch in `make_camera()`/`make_arm()`, add a profile YAML. Arm profiles pointing at the shipped **reBot** assets MUST carry `joint_signs: [-1]*6` (see contracts below); the SO-101 URDF is authored in the same convention its servos use, so it carries `[1]*5` — the sign list is per asset, not a house style. Heavy imports (pyrealsense2, ultralytics, pinocchio, zmq, mujoco, pyserial, the arm SDK) always stay lazy inside the branch/method that needs them so the mock stack imports nothing heavy.

**The arm's shape is data.** Common kinematic dimensions come from profiles; backend-specific clock, capture, payload and truth capabilities are validated explicitly. `n_joints`, joint limits, `home_q`/`handover_q`, `tool_axis_order`, gripper travel and the reachable envelope all come from the profile. Two mechanisms make that work and both are easy to defeat:
- `SkillRuntime._profile_q(key, what)` fetches joint-space keyframes and **raises** when a profile lacks one or its length disagrees with `n_joints`. Do not reintroduce a default — a 6-element reBot home pose broadcast onto a 5-DoF arm is a bent link, not a wrong answer. Every arm profile must therefore define `home_q` AND `handover_q`.
- An arm profile may carry an `overrides:` block that `load_demo_config` deep-merges over `demo.yaml` (workspace, `table_z`, `max_joint_vel`, grasp budget, `workspace_filter`). This is how one robot's rig geometry stops being everyone's. With `--arms a,b` only the PRIMARY arm's overrides land at top level; each arm's own view is at `cfg.arms[i].resolved`.
- Profiles support `extends: <parent>`, deep-merged (`so101_mock`/`so101_mujoco`/`so101_left`/`so101_right` are all thin children of `so101`). One physical arm, several transports, one place for the kinematic constants. `so101_mjwarp` extends `so101_mujoco` and changes exactly one line — `engine: warp` — so the MuJoCo Warp runtime is exercised against the SAME kinematic/gripper/workspace contract as the C engine; a divergence would mean the two sims describe different arms (`tests/test_mujoco_arm.py::test_mjwarp_profile_is_the_same_arm_on_the_warp_engine`).
- **MuJoCo backend, two runtimes (`control/mujoco_arm.py`).** One `MujocoArm` class, a pluggable engine underneath: `engine: mjc` (default) is the MuJoCo C runtime and the fast path for a single arm (~4.9 µs/step, ~1000× real time on an Apple laptop); `engine: warp` is MuJoCo Warp (`mujoco_warp.step`), driven single-world. MJWarp is a *batched GPU* engine — measured ~3.2 ms/step for one arm on Warp's CPU fallback here (macOS arm64, `warp-lang` reports only `cpu`), ~650× slower than the C engine but still ~1.5× real time, so the GPU path is developable on this Mac and accelerates on the DGX. The engine surface is batch-oriented (whole `qpos`/`ctrl` vectors via `d.ctrl.assign`, not per-joint scalars) because a per-scalar read crosses the host↔device boundary every tick under Warp. `device: auto` degrades CUDA→CPU with a warning, same contract as `device.py`. Physics tests are parametrized over every installed engine, so `[warp]` gets identical coverage to `[mjc]` including a cross-engine agreement check.

**Perception verified against physics, on two engines (`sim/mujoco_rgbd.py`, `tests/test_perception_truth_mujoco.py`, added 2026-08-31).** `grounding._recentre_by_size` corrects the centimetre-scale bias that made grasps catch an object's edge, and it was initially designed and measured **entirely on Isaac** through the bridge on `:8611`, without verification on another engine. `MujocoRGBD` renders offscreen RGB-D from an MJCF on CPU with `data.xpos` as ground truth, which reproduces the measurement on a laptop: **raw fitted OBB centre 2.27 cm mean / 2.64 cm max → de-biased 0.49 cm / 0.59 cm**, independently replicating Isaac's 1.85 → 0.56 cm. Two traps are baked into that module and must not be "simplified" away: (1) the camera must be **declared in the MJCF** — an `MjvCamera` posed from a transform via azimuth/elevation renders depth relative to its *lookat plane*, observed as `reported + true_range = 1.9533` for every range, i.e. depth **decreasing** as the prop moved away; (2) `cam_xmat` is (right, up, **backward**) while `mask_to_points_cam` wants OpenCV (right, **down**, forward). A test also pins the *premise* (the raw bias is really there), so a refactor cannot delete the correction with everything still green.

**Persistent spatial memory (`memory/beliefs.py` `save`/`load`, added 2026-08-31).** The ROADMAP's open item: the world model now survives a restart, so the robot does not re-discover a table it already mapped. The trap is that every belief timestamp is `time.monotonic()`, whose origin **resets with the process** — a naive `json.dump` round-trip yields negative ages and reports a stale belief as `visible`, which is worse than no memory because it looks authoritative. So timestamps are stored as **wall clock** and converted back on load, `LOADED_MIN_AGE_S` floors the apparent age so nothing restored can ever read as `visible`, and `DEFAULT_MAX_AGE_S` (6 h) drops yesterday's table. Writes are atomic (temp + `os.replace`) because the WorldWatcher may be fusing while the save runs. Wired in `build_runtime` (load) and `shutdown_runtime` (save, *first*, before teardown destroys its input); `memory.persist_beliefs: false` or `CASCADE_BELIEFS=0` disables it, `CASCADE_BELIEFS_PATH` relocates it. **A restored belief can never drive the jaws**: `_localize`'s existing `belief_fallback_age_s: 3.0` gate already refuses anything older, and restored beliefs are hours old by construction — they inform the agent, they do not aim it. `tests/conftest.py` has an autouse fixture pinning `CASCADE_BELIEFS_PATH` into `tmp_path`; without it a developer's real run leaks into the suite and a remembered object over empty mock table makes `pick_and_place` fail and escalate to the LLM (this actually happened, and surfaced as an unrelated-looking "LLM must not be called on the reflex path").

**Curriculum decomposition + warm start in the fast tier (`agent/reflex.py`, added 2026-08-31).** Agentic-VLA (arXiv:2605.22896) decomposes a task into sub-goals and warm-starts each from retrieved experience; its trainable parts (synthesized rewards, online policy updates) do not transplant to a frozen brain with analytic skills, but the *structure* does. `FastPlanner` now resolves reflex → experience → **curriculum**: `split_subgoals` splits on explicit sequence connectives only (`and then`/`then`/`luego`/`después` — never a bare "and", which would cut a single `pick_and_place` into two half-motions), then each clause is planned by experience recall first (that preference *is* the warm start) and the grammar second. This is **all-or-nothing**: one unplannable clause abandons the whole plan to the LLM, because running the prefix and reporting success is exactly the failure `parse_command`'s compound-command refusal exists to prevent. `FastPlan.subgoal_call_counts` records each clause's span at build time (a clause can compile to several calls, so re-deriving the split later mis-credits outcomes), and the orchestrator credits each sub-goal separately via `note_subgoal_outcome` — which is what makes it compound: a clause proven inside one sequence warm-starts any later task containing it. Net effect: "wave and then go home" no longer costs an LLM turn.

**Device agnosticism.** `cascade/device.py` is the only module that decides where a model runs: `resolve_device(spec)` maps `auto` to CUDA/ROCm → Apple MPS → CPU by probing the host, and an EXPLICIT device the host lacks degrades to the best available with a warning rather than raising (configs travel between machines; generic-device policy; required CUDA/GGX presenter and payload safety paths enforce their stronger contracts). `CASCADE_DEVICE` overrides every profile at once. Consumers: `perception/detector.py`, `perception/segmenter.py` (resolved lazily on first use — probing torch costs seconds), and the LIBERO baseline runner. **torch is deliberately not a dependency**: the correct build is per-platform. A hardcoded `cuda` in `configs/` fails `tests/test_device_and_profiles.py`.

**Feetech/SO-101 transport.** `control/feetech.py` is the pure wire protocol (framing, checksum, byte order, SYNC_WRITE) and is exhaustively unit-tested against a fake port; `control/feetech_arm.py` is the arm on top and is **UNVERIFIED on hardware**. Every register constant is an `(address, width)` tuple and all builders take that tuple, so an address can never be paired with the wrong width. Streaming uses one SYNC_WRITE frame per waypoint (N individual writes would blow the 20 ms budget on USB latency); reads are per-servo, so never add a read to the waypoint path. `stop()` is soft (re-assert the hold pose, torque ON); `hard_estop()` cuts torque and the arm FALLS. `scripts/diag_so101.py` is the read-only pre-flight plus a single-joint jog that reports which `wire_signs` entry to flip — it imports nothing from the package's config layer, because it exists for the case where the profile is wrong.

**MCP server.** `apps/mcp_server.py` is hand-rolled newline-JSON-RPC over stdio, and `stream_server.py` serves HTTP with stdlib `http.server` — both deliberate; don't add MCP-SDK or web-framework deps here. It hardcodes `llm='mock'`: the MCP host is the brain and the built-in tiers are bypassed. Stdout discipline: protocol frames only — every runtime call is wrapped in `redirect_stdout(sys.stderr)`, and since 2026-07-20 a stdin reader thread + worker queue share stdout, so protocol writes must go through `main()`'s locked `_send`; new code on this path must never print to stdout. The reader thread is the stop channel: `emergency_stop` frames are answered out-of-band mid-tool-call (a stop during the runtime build is held in `_stop_pending` and applied when the build finishes — never lost), `notifications/cancelled` on an in-flight `_MOTION_SKILLS` call latches the e-stop (guarded by `_cancel_lock` against the check/publish race), `ping` is answered from the reader, first SIGINT freezes (second exits — torque off), SIGUSR1 clears the e-stop (the staff reset channel), and `CASCADE_HIDE_TOOLS` delists+rejects tools (`emergency_stop` is never hideable; booth sessions hide `reset_stop`). **Capability matrix (`apps/capabilities.py`, added 2026-10-07, ROADMAP #12):** the catalog is further trimmed by what the BUILT rig can do, evaluated from probed state only — each camera stream's depth source via `DepthProvider.depth_source_for` (sensor / mono / plane / none, never a grab), the sidecar probes behind `runtime.backends()` plus `_graspgenx.status`/`_graspgenx_down`, `len(runtime.arm_rig)`, `cfg.bases`, `runtime.effects`, `runtime.memory`. `TOOL_REQUIREMENTS` (tool → capabilities) is the hand-maintained table; `withheld_tools()` returns tool → reason only for capabilities probed FALSE (tri-state: `None` = unknown never withholds, and `capability_matrix(None)` before the build withholds nothing — unprobed is not unavailable). On a single-arm rig `list_arms` goes and the injected `arm` property is deep-copied out of the served motion schemas (`TOOL_SPECS` is shared; never mutate it). The server rejects a withheld tool at call time AFTER `_ensure_runtime()` (a stale catalog cannot move the arm), reports the matrix in `world_state.capabilities`/`tools_withheld`/`tools_hidden_by_operator`, in the dashboard `/state` (via `_runtime_state`) and in the `[cascade] capabilities:` banner + `[cascade-mcp] tools withheld` log lines, and sends `notifications/tools/list_changed` (declared `listChanged: true`) when the surface changes after a catalog was served — `_surface_lock` makes that race-free against the prewarm thread. A FALLBACK is never a reason to hide: dead GraspGen-X/occupancy sidecars are reported, the grasp tools stay (no shipped tool strictly needs a sidecar; the strict path is pinned with a synthetic requirement). The stop path is never a capability. `CASCADE_ARMS=a,b` builds the ArmRig in MCP mode (mirror of `CASCADE_CAMERAS`); `configs/cameras/mock_rgb.yaml` (`rgb_only: true` on the mock camera) rehearses the RGB-only surface offline. Regression pins: `tests/test_review_regressions_v4.py`. The dashboard STOP button AND chat box are wired in MCP mode inside `_ensure_runtime` — don't remove them assuming demo.py's wiring covers it (that only runs in the CLI); the MCP-mode chat is reflex-grammar-only by design (`_reflex_chat_task`, the booth's host-outage fallback), never an LLM.

## Contracts & invariants

- **Composed robots:** `--robot` / `CASCADE_ROBOT` is opt-in. Read `docs/ROBOT_MODULARITY.md` before adding a domain. Describe resources from configuration without probing lazy drivers; claim the whole command endpoint, not just selected joints. Keep domain verifiers and physics clocks authoritative. Mixed physical actuation and mobile-mounted arms remain refused until shared-frame/whole-body admission exists. Sensor reads are passive and preserve epoch, capture time, provenance and modality; estimated tactile force is not solved support. Skill graphs use registered runtime tools and cannot reset stop permission or convert synthetic/unverified motion into physical success.

- **Units/frames:** positions in meters in the ROBOT BASE frame; joints in radians (degrees only in `get_observation` output). Base frame: +x away from robot, +y left; "left" = larger y. OBB convention everywhere: extents sorted descending, axes as matrix columns — never use `extent[2]` as height, use `top_z`.
- **`Frame.rgb` is BGR** (OpenCV) despite the name; `depth_m` is float32 metric meters aligned to color, 0 = invalid. `Frame.size` is (w, h) — opposite of numpy shape.
- **In-process perception/state timestamps (`Frame.t`, `RobotState.t`, belief ages, `MemoryEvent.t`) are `time.monotonic()`**, never wall clock — belief freshness math depends on it. Persisted/reporting timestamps (trace.jsonl, grasp-memory `saved_at`, dashboard status) are wall-clock `time.time()`; never mix the two.
- **Joint mirror:** both shipped RS assets (URDF and USD) are authored mirrored (`q_asset = -q_local`); `joint_signs` bakes the flip in at model load, so every constant in the repo (home_q, limits, tuned poses) is LOCAL. `tests/test_usd_model.py` pins URDF↔USD kinematic identity — it fires if you touch `assets/`. The SO-101 URDF is NOT mirrored (`[1]*5`), and there is a trap if you ever need a `-1` there: `usd_model.apply_joint_signs` walks joints in DOCUMENT order, and that URDF declares them backwards (gripper first, shoulder_pan last) relative to Pinocchio's kinematic order, so a sign list would be applied to the wrong joints. All-ones never invokes that path.
- **`n_controlled` slices the FIRST N joints** and zero-pads the rest, which is only correct because both shipped URDFs order the arm chain before the gripper. That is a property of the file, not a guarantee — check it for any new model (`tests/test_kinematics_so101.py::test_arm_chain_occupies_the_first_five_joint_indices` pins it for SO-101; the SO-101 URDF's *declaration* order is reversed and only Pinocchio's root-down traversal saves it).
- **`ik_task_weights` exists but no shipped profile uses it**, including the 5-DoF SO-101. Its wrist-roll axis is collinear with the tool approach (measured: rolling it turns the approach by 0.00°), so for a vertical approach the roll spends itself on jaw yaw and unweighted 6-DoF IK solves its workspace at 0.94. Do not "fix" the 5-DoF case by zeroing a weight — that makes IK accept poses the wrist cannot hold, replacing an honest failure with a silent wrong one.
- **`tool_axis_order` is per arm and not guessable.** `down_open` = columns [approach, open, third] (reBot); `open_down` = [open, third, approach] (LIBERO Panda AND the SO-101, whose fingers run along col2 with the jaws separating along col0 — measured from the Menagerie fingertip geometry). Getting it wrong rotates every grasp 90°, which is a past defect on the Panda path, not a hypothetical.
- **Error taxonomy** (`types.py`): `SkillError` = failure the agent should reason about; `SafetyViolation` = harness rejection; plain `RuntimeError` = crash/hardware fault. The orchestrator's recovery logic depends on this split.
- **Invariant:** `Kinematics.ik` `limit_margin` (0.025 rad) must stay strictly greater than the harness `joint_margin` (0.02) so IK never returns a pose the harness rejects — a past review defect; never tune one side alone.
- **Booleans from LLMs arrive as strings** ("false" is truthy) — coerce with the `_as_bool` pattern in any new skill taking a bool.
- Gripper `open_pos`/`closed_pos` polarity differs per arm profile (RS: open=-6.8 rad; mock: 0→1; Isaac: fraction, open=1.0; SO-101: open=+0.60 rad, closed=-0.15) — compute travel as `closed_pos - open_pos`, sign-aware.
- The SO-101 jaw is a single-hinge "beak", not parallel fingers: opening is NOT linear in motor angle and the jaw retracts along the approach as it opens. `max_width_m` is deliberately below the geometric gap at `open_pos` because the framework's angle→width map is linear; see the measured table in `configs/arms/so101.yaml`.
- Comments in control/safety/grasping encode rig-verified failure observations that tests rely on — preserve and extend them.

## Testing conventions

- **Retry-evidence admission:** `agent/aspire.py` must reject missing context, changed goals/arms/possession, unmeasured confirmations and matches across explicit reset/task-end rows. `SkillRuntime.execute()` captures resolved arm identity and possession BEFORE the skill, from the registry only — logging must never probe a `LazyArm` backend. Keep the focused tests in `test_agentic_upgrades.py` and `test_aspire_admission.py` with library/routing/verifier regressions. See `docs/DREAM_RSI_ADAPTATION.md`; a successful simulator demo is not evidence of causal learning or better grasp performance.

- Shared surface in `tests/conftest.py`: `REPO`, `URDF`, `USD`, `SO101_URDF`, `JOINT_SIGNS`, `has_pinocchio()`, `needs_pin`, `needs_pin_so101`, and the `demo_cfg` / `rng` fixtures. Import via `from conftest import ...`.
- **Do not gate a test on an optional extra when the contract can be faked.** CI installs neither `openai` nor `anthropic`, so an `importorskip("openai")` means the assertion runs on NO machine; `tests/test_hermes_brain.py` injects a stub `openai` module into `sys.modules` instead and asserts what the client was constructed with. Reserve real skips for things a stub cannot stand in for (physics, hardware).
- Tests that fake the host for `device.py` must clear the `lru_cache` on `_torch`/`best_device` at BOTH ends, and defensively (monkeypatch's finalizer runs after the fixture teardown, so `_torch` may already be a plain function by then).
- E2E tests build the real pipeline with `build_runtime(cfg, tmp_path / "run")` on the mock stack; control grasp outcomes with `arm.object_stop_frac` (0.5 = object held, None = air-grasp). Always poll `runtime.beliefs.find("red object")` in a deadline loop before executing skills (the watcher thread needs a detector pass), and tear down with try/finally `shutdown_runtime(runtime, arm)` — these are real threads.
- Config overrides in tests mutate `cfg._data[...]` directly; there is no override API. Servers bind port 0; `MockLLM(responses)` plays a script and records `.requests` for assertions. **Build HTTP test URLs from `conftest.loopback_host()`, never a literal `127.0.0.1`** — with some VPN clients active (a `utun` interface holding 198.18.0.0/24) a connection to the numeric loopback is intercepted and closed (`RemoteDisconnected`) while `localhost` works, which made six streaming/live-view/MCP tests fail for reasons unrelated to the code.
- `tests/test_review_regressions*.py` is a convention: each adversarial review pass gets its own file, one test per confirmed defect with the root cause in the docstring (v1 = 2026-07-16 review, v2 = livestreaming review, v3 = late pins for v1 fixes). New review findings get their own vN file, not silent folding into feature tests.
- `scripts/` modules are tested via `sys.path.insert(0, str(REPO / "scripts"))`, not packaging.

- **`--llm` defaults to `auto`**, which resolves to `hermes` / `anthropic` / `openai` if the matching key is exported, else `mock`. Do not remove the flag to "get more verification": it produces false negatives, not evidence.
