Your 20-second introduction

Start with what they can do.

“This is PAAI, Physical Agentic AI. You can ask about the kitchen or give the robot a task in plain English. We'll watch it through three cameras, then check whether it moved the right object. Start by asking what it can see.”

Before a group arrives

  1. Open the attendee page. Check Kitchen, Worktop and Side for current images and wait for Live.
  2. Use the connected OpenClaw chat on the booth computer. Keep Worktop beside it. This page and the attendee link do not send robot commands.
  3. Wait for any active task to finish. Reset once and check that the arm and loose props return to their starting places.

Walk through one task

1 · Look

Inspect the scene

Compare the chat reply with Worktop. It shows the objects and the green delivery square. The green cube is a separate object.

2 · Move

Send one request

Choose one object and a clear destination. Watch the lift in Side. A pick can take about one to two minutes; wait for the full reply.

3 · Check

Read the result

Watch the release and settled object in Worktop. Kitchen shows the whole room. Review the tool result together, then reset.

The green square is the delivery zone. Use the single loose orange near the arm; the oranges on the plate are outside the grasp area. The lemon can be hard to identify and grasp.

If the scene description is unclear

Try this guided observation prompt, then compare the reply with Worktop:

Call get_observation once for a fresh view. Describe only the objects, colors and shapes visible in the returned image. Say when something is unclear; do not treat configured destinations as proof that an area is visible or empty. Use at most three short sentences. Do not move anything or call another tool.

What a successful run looks like

The requested object lifts clear of the counter, stays in the gripper during the move, and settles fully inside the green border after release. Check Side for the lift and open jaws, then Worktop for the final position.

After the movement, ask:

Check the object's final position using physics. What does the evidence confirm, and what is still unverified?

Keep an unverified result as unverified. A position near the zone's center does not by itself prove full containment or release. If the views and readback disagree, pause and have the demo operator review the result.

Successful orange and tomato-can pick/place cases have been checked with camera images and simulator physics. Guided scene inspection, locating the delivery zone, authenticated camera streaming and reset/recovery have also been tested. Each new run still needs its own check.

If something goes wrong

Missed grasp or dropped object

Let the current tool finish. Say, “The gripper missed; this attempt did not complete the task.” Read the result, then reset once. Do not queue retries while the arm is moving.

If it keeps missing, return to scene inspection and ask the demo operator for help.

Old or frozen camera

Pause new movement requests. Let the page reconnect, then refresh it if needed. Check all three views; a Live label alone is not enough if the image stays frozen during motion.

If a view remains stale, let the active task finish and have the operator check the feed. Request a fresh observation before the next movement.

Reset between tasks

A new chat does not reset the scene. Wait for the current tool to finish. If a normal reset request did not trigger a tool call, send this once:

Call reset_scene now for a fresh reset. Call it exactly once and wait for the tool result. Reply briefly in English, then stop.

Check for an empty gripper at home, the loose props back in their starting positions and current images from all three cameras. Leave a failed reset result in the chat and ask the operator to recover the demo before another turn.

Known limits

  • This is a simulation with a small set of prepared objects and skills. It does not establish performance on physical hardware.
  • Object descriptions can be wrong, especially with the lemon or partly hidden objects. Compare them with the current view.
  • Grasps and unusual arrangements can fail. Do not promise that every request will work.
  • Camera previews update only a few times per second. Smooth playback does not mean the scene is captured at that rate.
