## VERSIONING

- **"OpenClaw 2.0" is a marketing name, not a version number.** The release published as "OpenClaw 2.0" (announced 2026-08-31) is **`v2026.8.1`** — CalVer continues unchanged. There is **no `2.x` semver on npm**: dist-tags as of 2026-09-03 are `latest → 2026.8.2`, `beta → 2026.9.1-beta.1`, `extended-stable → 2026.6.34`.
  - Sources: https://registry.npmjs.org/openclaw (dist-tags/versions), https://github.com/openclaw/openclaw/releases (tags `v2026.8.1` 2026-08-31, `v2026.8.2` 2026-09-01), https://infoq.com/news/2026/09/openclaw-2-release ("The release corresponds to version 2026.8.1"), https://time.news/openclaw-2-0-launches-with-crowdsourced-redesign-and-simplified-setup ("OpenClaw v2026.8.1 (aka OpenClaw 2.0)").
- Your verified baseline `2026.7.1-2` (2026-08-04) → 2.0 is one stable hop; `2026.8.2` is the first post-2.0 patch (it fixes 2.0 migration bugs — prefer it over 2026.8.1). Source: https://github.com/openclaw/openclaw/releases.
- Big-bang release: ~7 weeks of work, 16k+ PRs, storage migrated from flat files to **SQLite** (sessions, transcripts, memory). Upgrades from 2026.7.x run a one-way state migration; the release notes tell you to back up `~/.openclaw` first, and `openclaw update cleanup --dry-run` (new) previews retained pre-migration originals. Sources: https://github.com/openclaw/openclaw/releases/tag/v2026.8.1, https://github.com/openclaw/openclaw/releases/tag/v2026.8.2 (Recovery cleanup), https://infoq.com/news/2026/09/openclaw-2-release.
- **Disambiguation:** NVIDIA **NemoClaw** is a separate product — a host CLI (`nemoclaw`, currently v0.0.117–v0.0.119) that runs OpenClaw inside **OpenShell** sandboxes. Its docs live under docs.nvidia.com/nemoclaw but describe the *wrapper*, not the OpenClaw CLI itself. OpenClaw-proper docs are at https://docs.openclaw.ai. Sources: https://docs.nvidia.com/nemoclaw/user-guide/openclaw/about/ecosystem.md, https://docs.nvidia.com/nemoclaw/user-guide/openclaw/release-notes/2026/9/2.md.

## MULTI-AGENT FEATURES (new/expanded in 2.0)

- **Named multi-agent roster.** `openclaw agents list|add|delete|bind|unbind|bindings|set-identity`; agents are isolated (own workspace, own `agentDir` with per-agent auth + SQLite session store); inbound traffic routes to agents via deterministic, most-specific-wins **bindings** (`openclaw agents add ops --workspace ... --bind telegram:ops --non-interactive`). Onboarding can name the first agent (`--agent-name`); `main` is now an ordinary agent id. Sources: https://docs.openclaw.ai/cli/agents.md, https://docs.openclaw.ai/concepts/multi-agent.md, https://docs.openclaw.ai/cli/onboard.md
- **Sub-agents / orchestration tools.** Agent-facing tools `sessions_spawn` (spawn isolated background run, session key `agent:<id>:subagent:<uuid>`, announces result back), `sessions_yield`, `subagents` (list/cancel), plus cross-session `sessions_list`/`session_status`/`sessions_send`/`sessions_history`. Config: `agents.defaults.subagents.maxSpawnDepth` (1..5), per-agent `subagents.allowAgents` allowlist (`["*"]` = any; default = same agent only), `subagents.model` for cheaper child models, sandbox inheritance guard (sandboxed parents cannot spawn unsandboxed children). `/subagents list|log|info` slash command for inspection. Sources: https://docs.openclaw.ai/concepts/session-tool.md, https://docs.openclaw.ai/tools/subagents.md, https://docs.openclaw.ai/gateway/config-agents.md
- **Swarm (experimental, Labs).** Bounded parallel fan-out of subagents with structured result collection — `src/agents/subagents/swarm/` is new at v2026.8.1 (absent at 2026.7.1-2). Source: https://github.com/openclaw/openclaw/releases/tag/v2026.8.1 ("Experimental Swarm"); repo tree diff; https://docs.openclaw.ai/tools/swarm
- **Multiple MCP servers: already supported, now richer.** `mcp.servers.<name>` map (stdio | sse | streamable-http); per-server `toolFilter.include/exclude` (globs), `enabled: false`, per-server `requestTimeoutMs`/`connectionTimeoutMs`, `supportsParallelToolCalls`, OAuth (incl. per-requester identity), mTLS. A broken server is paused briefly rather than consuming the turn; one-shot runs (`openclaw agent`, `agent exec`) tear down stdio MCP child process trees at run end. Source: https://docs.openclaw.ai/cli/mcp.md
- **Tool namespacing.** MCP tools surface as `<server>__<tool>` (e.g. `docs__read_page`) — this naming already existed at 2026.7.1-2 (same example in in-repo docs at that tag), so **no rename risk for cascade's 38 tools**. New in 2.0: runtime tool allowlists accept server globs (`server*`), and OpenClaw-configured MCP servers now obey conversation/session tool policy in Claude/Codex/Gemini backends too. Sources: https://docs.openclaw.ai/cli/mcp.md (probe output), repo docs @ v2026.7.1-2; https://github.com/openclaw/openclaw/releases/tag/v2026.8.1 (MCP server globs, Native MCP policy)
- **Node-hosted MCP servers.** Paired nodes can host MCP servers/plugin tools without duplicating config on the Gateway (no OAuth servers yet; node restart applies changes). Relevant future option: run cascade's MCP server on the robot host while the Gateway lives elsewhere. Source: https://github.com/openclaw/openclaw/releases/tag/v2026.8.1 ("Node-hosted tools")
- **External supervision mode.** `OPENCLAW_SUPERVISOR_MODE=external` lets your own supervisor (systemd unit, booth script) own Gateway restarts/updates without fighting the native service — useful if `booth_up.sh` should own lifecycle. Source: https://github.com/openclaw/openclaw/releases/tag/v2026.8.1
- **NemoClaw-specific (only if driving OpenClaw through NVIDIA's stack):** declarative multi-agent manifest `nemoclaw onboard --agents ./agents.yaml` bakes `agents.entries`/`agents.defaults.subagents` into the sandbox image, mirroring OpenClaw's sub-agents schema. Source: https://docs.nvidia.com/nemoclaw/user-guide/openclaw/configure-agents/declarative-agents-manifest.md

## GOTCHAS (what breaks / improves vs your 2026.7.x notes)

1. **PYTHONPATH is still blocked for stdio MCP servers — unchanged.** `src/infra/host-env-security-policy.json` lists `PYTHONPATH` (and `PYTHONHOME`, `NODE_OPTIONS`, `LD_*`, `DYLD_*`, `BASH_ENV`, …) in `blockedEverywhereKeys` at v2026.7.1-2, v2026.8.1 **and** v2026.8.2; tests assert the exact warning `env "PYTHONPATH" is blocked for stdio startup safety and was ignored` (`src/agents/mcp-transport-config.test.ts` @ v2026.8.1). Blocked keys are dropped silently with a log warning; ordinary `*_API_KEY`/proxy/credential vars stay allowed. **Keep the editable-install workaround.** Sources: https://github.com/openclaw/openclaw/blob/v2026.8.1/src/infra/host-env-security-policy.json; https://docs.openclaw.ai/cli/mcp.md ("Stdio env safety filter").
2. **`--cwd` and `--env` survive verbatim.** Both are current documented `mcp add` stdio flags; config keys `cwd`/`workingDirectory` and `env` unchanged; `openclaw mcp doctor` now statically checks that `cwd` exists and the command resolves — run `openclaw mcp doctor cascade --probe` after `mcp add` for a stronger step-5 check than `mcp probe` alone. Source: https://docs.openclaw.ai/cli/mcp.md.
3. **Gateway restart after `mcp add` is still required.** New `openclaw mcp reload` only disposes cached MCP runtimes **in the current CLI process**; "Gateway or agent processes in another process still need their own reload or restart path." Keep step 4's `openclaw gateway restart`. Source: https://docs.openclaw.ai/cli/mcp.md.
4. **contextWindow patch: partially fixed, keep the guard.** The generic self-hosted default is still `SELF_HOSTED_DEFAULT_CONTEXT_WINDOW = 128000` (identical at both tags, `src/agents/self-hosted-provider-defaults.ts`). New in 2.0: the llama.cpp external-server path (`extensions/llama-cpp/src/external-server/models.ts`, absent at 2026.7.1-2) reads real `n_ctx` from `/props` — so the **qwen** brain path may self-correct **if onboarded via a llama.cpp-aware auth choice**; the vLLM/`custom-api-key` path (cosmos brains) still gets 128000. Your `/props`-probe + `~/.openclaw/openclaw.json` patch remains the safe move; the file path and `models.providers.*.models[].contextWindow` shape are unchanged (`contextTokens` added as a separate active-input cap). Sources: repo files at both tags; https://docs.openclaw.ai/gateway/config-agents.md.
5. **Half-onboarded config still blocks gateway start — now with an escape hatch.** Missing `gateway.mode` is still treated as damaged config and the Gateway refuses to guess; new `openclaw gateway run --allow-unconfigured` bypasses for ad-hoc runs (does not persist). Your `config set gateway.mode local` pre-step remains valid. Source: https://docs.openclaw.ai/cli/gateway.md.
6. **Onboard/gateway ordering can be simplified.** `onboard --non-interactive` still health-checks a local gateway, but `--skip-health` (config writes only) already existed at 2026.7.1-2 and remains in 2.0 — with it you could do mcp add → onboard → single gateway install/start, dropping the start-then-restart dance to one restart. Sources: https://docs.openclaw.ai/cli/onboard.md; `docs/cli/onboard.md` in openclaw/openclaw at both v2026.7.1-2 and v2026.8.1.
7. **Upgrade path is the real risk, not the CLI.** 2.0 migrates state to SQLite and `agents.list`→`agents.entries`; community reports include broken gateways and lost automations on upgrade (InfoQ). Recipe: back up `~/.openclaw`, `openclaw update`, `openclaw doctor --fix`, `openclaw config validate`, then re-run `scripts/openclaw_demo.sh` (it is idempotent). On a fresh 2.0 install none of this applies. Sources: https://github.com/openclaw/openclaw/releases/tag/v2026.8.1, https://infoq.com/news/2026/09/openclaw-2-release, https://docs.openclaw.ai/cli/doctor.
8. **`ss -ltn` port probe still works** (default port `18789` unchanged), and `openclaw gateway status`/`gateway probe`/`gateway health --port 18789` are the supported checks. Source: https://docs.openclaw.ai/cli/gateway.md.
9. **If you ever route through NVIDIA NemoClaw instead of bare OpenClaw:** NemoClaw's managed MCP accepts **Streamable HTTP endpoints only — no stdio, no host-side stdio-to-HTTP bridge** ("Host-side MCP bridges, proxies, relays, listeners, and stdio translation are explicitly out of scope"). Cascade's stdio server would have to be registered inside the sandbox with OpenClaw's own `mcp add`, or exposed as a streamable-HTTP server. NemoClaw sets context via `NEMOCLAW_CONTEXT_WINDOW` env at onboard (build-time; sandbox recreation to change). Sources: https://docs.nvidia.com/nemoclaw/user-guide/openclaw/manage-sandboxes/mcp-servers/about-managed-mcp-servers.md, https://docs.nvidia.com/nemoclaw/user-guide/openclaw/inference/manage-inference/configure-model-limits.md.
10. **New verification niceties worth adopting:** `openclaw mcp doctor cascade --probe` (static + live proof, credential-redacting, warns on literal secrets in `--env`); `openclaw agent exec "describe the scene" --json` as a Gateway-free headless smoke test; `openclaw update --tag 2026.7.1-2` to pin/roll back a one-off npm version. Sources: https://docs.openclaw.ai/cli/mcp.md, https://docs.openclaw.ai/cli/agent.md, https://docs.openclaw.ai/install/development-channels.md.

## INSTALL ONE-LINER

```bash
# OpenClaw 2.0 (Gateway + onboarding wizard)
curl -fsSL https://openclaw.ai/install.sh | bash

# unattended (for bootstrap.sh-style chaining; skips the wizard)
curl -fsSL https://openclaw.ai/install.sh | bash -s -- --no-onboard

# CLI-only variant
curl -fsSL https://openclaw.ai/install-cli.sh | bash

# pin a version (post-install)

```

Same URL as the 2026.7.x era — no change needed in `scripts/bootstrap.sh`. Sources: https://docs.openclaw.ai/install.md, https://docs.openclaw.ai/install/installer.md, https://docs.openclaw.ai/install/development-channels.md.

For NVIDIA NemoClaw (the sandboxed wrapper, a different product): `curl -fsSL https://www.nvidia.com/nemoclaw.sh | bash` (`NEMOCLAW_NON_INTERACTIVE=1`, `NEMOCLAW_ACCEPT_THIRD_PARTY_SOFTWARE=1` for automation). Source: https://docs.nvidia.com/nemoclaw/user-guide/openclaw/get-started/quickstart.md.

### Bottom line for `scripts/openclaw_demo.sh`

Every command and flag the script uses (`mcp add --command/--arg/--cwd/--connect-timeout/--env`, `config set gateway.mode local`, `gateway install/start/run/restart`, `onboard --non-interactive --accept-risk --mode local --auth-choice custom-api-key --custom-*`, `mcp probe`, `config validate`, `agent --agent main -m`, port 18789) is **present and unrenamed in 2.0**. The PYTHONPATH block, the contextWindow=128000 default for custom OpenAI-compatible providers, and the restart-after-mcp-add requirement all persist — keep all three workarounds. The only mandatory action is the **upgrade itself** (SQLite + agents.entries migration): back up `~/.openclaw`, then `openclaw update && openclaw doctor --fix && openclaw config validate` before re-running the demo script. Optional improvements: add `--skip-health` to onboard, swap `mcp probe` for `mcp doctor cascade --probe`, and use `openclaw agent exec ... --json` for CI smoke tests.
