## Why twelve in one world worked here and not in the route runs

The route fleet (`docs/evidence/microduck-route-fleet-20261005/`, PR #222) failed with twelve robots in
one world because twelve closed-loop *clients* polled the owner's RPC threads and tripped the
unchanged 0.4 s progress / 0.5 s state-age limits. The showcase has **no clients**: every twist
is computed inside the owner's `control_at`, so the owner ran at 61 ms per step and the only
freshness rule in play (the controller's own 0.5 s state age, still enforced for scripted twists)
never tripped. This does not close the roadmap row about twelve verified robots in one world;
it is a presentation of the same policy, BAM and simulation under scripted commands.

## Honest limits

- The presenter is a kinematic visual proxy: no collision with the robots, pose from the
  simulation clock (oracle), no perception anywhere.
- Scripted twists are not agent tasks; there is no independent verifier and no verdict.
- Path length integrated from 50 ms rows (9.9–10.1 m) is inflated by gait sway and is not a
  locomotion figure; use the net displacement.
- Robot-paced presenter: 0.20 m/s with pauses, far below a walking human.
