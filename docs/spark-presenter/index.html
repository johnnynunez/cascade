01 / Install once

Prepare a new Spark from start to finish.

Open a terminal on the Spark, as your normal user, not root. Use the same terminal for these steps. Run each block once; wait for its success message and exit code 0 before continuing.

Before you start: hardware, disk and network
  • Host: a DGX Spark running Linux aarch64, glibc 2.35 or newer, a working NVIDIA driver compatible with CUDA 13 and a CUDA toolkit with nvcc. DGX OS supplies the driver and toolkit; this installer does not replace either or upgrade the OS.
  • Space: at least 150 GiB free on the home volume, plus room for later recordings and shader caches. Check any separate cache volume too.
  • Desktop: use the Spark’s graphical session for Chromium and the app-grid launcher. SSH can prepare and verify the installation, but cannot open a browser on your laptop automatically.
  • Downloads: outbound HTTPS to GitHub and Git LFS, Hugging Face and its file hosts, PyPI, NVIDIA and PyTorch package indexes, astral.sh, openclaw.ai, Node.js and npm, including redirects.
  • One stack: resolve occupied ports before starting. Do not stop somebody else’s process to free a port; see ports and remote access.

Use a clean shell without overrides from another installation: ISAACSIM_PATH, ISAACSIM_PYTHON_EXE, CASCADE_QWEN_MODEL, CASCADE_QWEN_MMPROJ, LLAMA_DIR or LLAMA_SERVER.[2]

  1. Choose the installation folder

    The default is $HOME/paai-spark. For a fresh install, the destination must not exist; the installer creates it. Do not create an empty folder first.

    Keep an existing installation unchanged. If the demo is already installed and you only want to run it, skip to Start & connect. For a separate installation, choose a path that does not yet exist:

    Optional separate installation folder
    export PAAI_INSTALL_DIR="$HOME/paai-spark-new"

    Check Your chosen destination does not exist and is not the working event installation. An intentional retry may reuse the checkout created by an earlier installation attempt.

    Keep PAAI_INSTALL_DIR exported for the remaining steps. In a new terminal, export the same path again. Use the exact launcher path below for that installation; these commands never change HOME.

  2. Check the host prerequisites

    Spark terminal · read-only host check
    bash -o pipefail -c 'curl -fsSL https://raw.githubusercontent.com/johnnynunez/cascade/9cf540279f09df8197eda6541311b41edb455243/scripts/spark_prerequisites.py | python3 -'

    Check PREREQUISITES_OK.

    Missing packages, curl or python3? Administrator step

    Skip this when prerequisites already pass. If the check reports missing system packages, an administrator runs:

    Administrator · only for missing packages
    sudo apt-get update && sudo apt-get install -y git git-lfs curl python3 ca-certificates build-essential libgomp1 libglib2.0-bin gnome-terminal chromium-browser && printf 'PACKAGES_READY\n'

    Check: PACKAGES_READY. Repeat the prerequisite check once. Driver or CUDA toolkit failures need the Spark administrator; this command does not install those.

    Use Chromium for automatic extension loading. Branded Chrome 137 and newer does not accept the automatic loading flag. Over SSH, missing desktop tools may be warnings; the graphical launcher still needs them.

  3. Install the complete demo

    License consent: the NVIDIA Isaac Sim / Omniverse licenses require your explicit acceptance. The --accept-eula flag records that consent for this checkout. If you already accepted this Isaac version for the task, proceed without another confirmation; a coding agent records your authorization rather than inventing consent.

    Allow 30–90 minutes plus cold CUDA builds as a planning estimate, not a measured time for this candidate. Downloads can take longer. The installer downloads dependencies and builds the CUDA model server. Keep the progress log.

    Spark terminal · after explicit EULA acceptance
    bash -o pipefail -c 'curl -fsSL https://raw.githubusercontent.com/johnnynunez/cascade/9cf540279f09df8197eda6541311b41edb455243/scripts/bootstrap.sh | bash -s -- --ref 9cf540279f09df8197eda6541311b41edb455243 --profile spark --accept-eula --prepare-only --dir "${PAAI_INSTALL_DIR:-$HOME/paai-spark}" 2>&1 | tee "${PAAI_INSTALL_DIR:-$HOME/paai-spark}-install.log"'

    Check PREPARED. Files are prepared; no demo services or startup manipulation tests have run.

    What that one command installs
    • App and simulator: Python 3.12, cascade and CUDA perception packages in .venv/; Isaac Sim 6.1.0.0 with its extension cache in .isaacsim/.
    • Learned grasps: the private CUDA GraspGen-X environment in .graspgenx/, pinned model source and full generator/discriminator checkpoints in .graspgenx-src/. Live inference is checked during launch.
    • Local brain: the pinned Qwen3.8-27B Q4 model and BF16 vision projector in models/qwen3.8-27b/, plus the pinned llama.cpp CUDA server in .llama.cpp/build/. No model API key.
    • Agent: OpenClaw 2026.9.3 and private Node.js in .openclaw-cli/. The demo uses its own cascade-demo profile, not your personal OpenClaw gateway.
    • Robot and scene: Git LFS robot assets, perception weights, verified Cocina Asier kitchen geometry and task props. The installer verifies the downloaded scene archive and extracted asset hashes.
    • Desktop integration: the PAAI camera extension and registered launcher. Chromium itself comes from the administrator’s system-packages step, not the bootstrap. Private runtimes and consent are recorded in runs/.install/install.json.

    The installer obtains uv and Python when needed and reuses verified downloads. No separate standalone Isaac, GraspGen-X, OpenClaw or Qwen install is needed. Moving the checkout requires installation to record the existing authorized consent at its new path; do not edit the receipt.

  4. Verify the installation without starting it

    Spark terminal · read-only install check
    cd "${PAAI_INSTALL_DIR:-$HOME/paai-spark}" && bash scripts/install.sh --profile spark --dir "$PWD" --check && printf 'CHECKED\n'

    Check CHECKED. This is read-only: it starts no services and accepts no license.

    The receipt is runs/.install/install.json. CHECKED proves preparation, not robot or camera readiness.

  5. Start once and wait for the physical proof

    This starts the local model, simulator and OpenClaw, then moves the simulated robot through green-cube and orange placements and resets. It does not connect to a real robot.

    Spark terminal · starts and proves the simulated demo
    (
  set -o pipefail
  cd "${PAAI_INSTALL_DIR:-$HOME/paai-spark}" || exit
  python3 scripts/desktop.py launch --repo "$PWD" --headless --no-open 2>&1 |
    tee "${PAAI_INSTALL_DIR:-$HOME/paai-spark}-launch.log" | awk '/^\[desktop\]/ { print; fflush() }'
) && python3 "${PAAI_INSTALL_DIR:-$HOME/paai-spark}/scripts/spark_verify.py" --repo "${PAAI_INSTALL_DIR:-$HOME/paai-spark}" --expected-ref 9cf540279f09df8197eda6541311b41edb455243

    Check One READY summary: both placements, camera evidence and resets pass, with current health and process ownership verified.

    An earlier revision’s measured start and proof took about 14 minutes; this is not a timing guarantee for the candidate. A cold start may take longer. The checks can be quiet for several minutes. Keep waiting; do not run a second launch just to obtain more output. Full output stays in ${PAAI_INSTALL_DIR:-$HOME/paai-spark}-launch.log.

    Next: open the desktop interface and check the three live cameras. Opening the launcher attaches to this accepted running stack instead of repeating the proof.

Installation or first launch failed
  1. Stop at the failed step. Preserve ${PAAI_INSTALL_DIR:-$HOME/paai-spark}-install.log or the launch log.
  2. For installation, correct only the reported package, network or disk problem. Repeat the same pinned install block once; it reuses verified files.
  3. For startup, use service recovery. If the failure returns, send the first error and log path to the operator.

Do not delete environments, edit receipts, change the model or physics, or skip proof to obtain READY. PREPARED and CHECKED are not READY. Exit 2 means rejected arguments, consent or prerequisites; a read-only check exiting 3 reports missing components.[2]

02 / Start & connect

Open the right interface.

  1. Start once

    For a single installation, click PAAI (Spark) in the app grid. With several installations, use the exact launcher command for your chosen folder: their app-grid names can be identical. If startup is already running, wait. Do not start a second copy.

    Open the same launcher from a graphical terminal

    Use this for the folder selected during installation. Keep its PAAI_INSTALL_DIR exported in this terminal.

    Spark desktop terminal · opens the selected installation
    gio launch "${PAAI_INSTALL_DIR:-$HOME/paai-spark}/runs/.install/paai-spark.desktop"

    The launcher opens a dedicated Chromium profile with the PAAI extension already loaded. No manual extension install or token paste is needed on this supported desktop path.

    Check Startup reports READY and the three camera views advance.

    A fresh start runs placement tests and resets. Reopening an accepted running stack attaches without repeating them. Use scene reset between visitors; it keeps services running.[2]

  2. Open native OpenClaw

    Open a terminal on the Spark desktop. Copy and run:

    Spark terminal
    cd "${PAAI_INSTALL_DIR:-$HOME/paai-spark}" && ./run.sh dashboard

    Check Native OpenClaw opens, normally on port 18790. The command handles the current sign-in link.

    The page at http://127.0.0.1:8092 is PAAI’s own WebUI, not native OpenClaw. Do not copy tokens from openclaw.json. If the command says unknown mode 'dashboard', use Older installs.[2][10]

  3. Check all three cameras

    In that OpenClaw window, click the PAAI camera extension or press Ctrl + Shift + Y. Reconnect if prompted.

    Check Kitchen, Worktop and Side show changing live images.

    If any view is unavailable, stop here and recover the cameras. Use one operator chat; every chat controls the same kitchen.[3]

03 / Present & reset

One order. Watch. Reset.

Copy a prompt into the connected OpenClaw chat. These buttons only copy text; they never send an order.

First, inspect the scene

What can you see on the table?

Compare the answer with Worktop. If it is wrong, ask for a fresh observation before moving.

Then, move the green cube

Could you put the green cube in the green square?

Check Wait for the tool result and the arm to finish. The cube must be released inside the square, not merely nearby.

After the action finishes, reset

Reset the scene.

You can also use Reset in the PAAI OpenClaw interface or Start over in the Spark WebUI where available.

Check The reset tool succeeds, the arm is home, the gripper is empty, the props are back and all camera views advance.

After reset, try the orange

Please put the orange in the open box.

Check release inside the box. Reset again before the next visitor.[2]

A new chat does not reset the kitchen. Reset first; then open a new chat for the next attendee.

Keep an unverified result unverified. A confident chat reply does not prove success.[3]

04 / Recover

Stop new orders. Pick the symptom.

Keep the last tool result. A lost reply does not prove that the action never happened.

The scene needs a reset

If the stack still responds, wait for the current action to finish and click Start over in the Spark chat, or send “Reset the scene.” Keep this chat open until the result arrives.

This restores props, returns the arm home, clears object beliefs and task images, and obtains a fresh observation. It does not repeat startup tests or erase learned grasps, recent text memory or chat history. A failed reset is not a restored scene.

Do not restart Isaac or delete memory files just to put the objects back.[3]

A camera says “unavailable”
  1. Keep movement requests paused.
  2. Reopen native OpenClaw with ./run.sh dashboard from the installation folder. Supported revisions use the dedicated PAAI Chromium profile.
  3. Open the extension and choose Reconnect. Check all three views.
  4. If it still fails, run this read-only check on the Spark.
Read-only check
cd "${PAAI_INSTALL_DIR:-$HOME/paai-spark}" && \
python3 scripts/spark_browser.py --repo "$PWD" --check

Check: it prints READY or NOT READY. This checks the accepted stack, cameras and chat together; NOT READY does not identify the camera fault by itself. Save the result for the operator.[8]

An older extension may lack Spark-native camera discovery. Record the installed revision before changing browsers or reinstalling anything.[11]

The chat disconnected

Run the dashboard command again. It reads the current sign-in information. Do not paste authentication URLs or gateway tokens into Slack.

Check: the chat is connected and accepts input. Read the last tool result before repeating an order.[2]

A service crashed
  1. Stop new orders and record the first error shown by the launcher.
  2. From the installation folder, stop this checkout’s stack.
Stops this checkout’s stack
cd "${PAAI_INSTALL_DIR:-$HOME/paai-spark}" && ./run.sh down
  1. Open the exact launcher for the same installation once. Do not choose between identically named app-grid entries.
  2. Wait for the result, then return to the start checklist. If it fails again, stop retrying and send the operator the error and log path.
Startup failed after a memory-cleanup script

Keep the script and the failing log. Do not run the cleanup again until the operator has reviewed it.

Resetting objects, starting a new chat and deleting learned memory are different operations. The cause of the reported startup failure is not established.

Never delete the installation or launch-state folders as a shortcut.

Skip manipulation proof only in the lower-level launcher

If Qwen is still running, this restarts missing robot services and checks learned inference, tools and scene identity while skipping startup manipulation and the optional image judge:

Spark terminal · lower-level restart, Qwen already running
cd "${PAAI_INSTALL_DIR:-$HOME/paai-spark}" && ./run.sh isaac --engine physx --graspgenx local --no-robot-turn --no-judge

Keep any scene and display options used for this installation. The desktop entry rejects the skip flags, and camera/chat attachment requires a verified proof. This is not a complete fast-restart recipe for the PAAI desktop icon. Use the normal desktop start if Qwen or those surfaces also need recovery.

Skipped proof means STARTED (UNVERIFIED: robot proof skipped), not READY. Do not edit proof receipts to bypass this.[6][7][8]

05 / Operator notes

Keep the event version fixed.

Record the installed revision and local edits before changing the event machine. A documentation update on main does not update an installed checkout.

Read the installation receipt without printing tokens

Run this on the Spark. It prints only the source revision, recorded dirty state, profile and brain.

Read-only receipt
cd "${PAAI_INSTALL_DIR:-$HOME/paai-spark}" && python3 - <<'PY'
import json
from pathlib import Path
p = Path("runs/.install/install.json")
d = json.loads(p.read_text())
for key in ("source_commit", "source_dirty", "profile", "brain"):
    print(f"{key}: {d.get(key, 'not recorded')}")
PY

This is an installation receipt, not proof that files are unchanged now. Also record local edits, including visible-Isaac and cleanup changes.[2]

PhysX, learned grasps, optional experiments and visible Isaac

The candidate Spark launcher selects PhysX CUDA, local Qwen Q4 and real GraspGen-X. It starts the private model server and checks actual diffusion inference. An absent server, stub or failed required inference must be reported; OBB does not validate the learned-grasp setup.[6]

The desktop command defaults to headless Isaac. To show the editor, run python3 scripts/desktop.py launch --repo "$PWD" --gui from the installed folder. Stop this checkout’s stack before changing the display mode of an already running bridge. Rehearse the same display setting used at the event.[7]

Newton is an explicit engine option under separate validation. Occupancy/nvblox is disabled in the presenter profile; JEv is not installed or active. These experiments and arbitrary object rearrangement need their own rehearsal and do not belong in the first-install path.

Older installs: “unknown mode 'dashboard'”

The former guide pinned 57ecd62dfec3fb361c6db8ee3c096293aec77ca8, which predates the real GraspGen-X launcher. Do not combine its install command with this candidate’s component assumptions.

The older fac5332416f688fd5d035e0b0a8088d52ef4d469 install does not include ./run.sh dashboard. Its documented native-UI fallback, on the Spark desktop, is:

Older-install fallback
cd "${PAAI_INSTALL_DIR:-$HOME/paai-spark}" && \
OPENCLAW_STATE_DIR="$PWD/runs/.launch/profile-cascade-demo/openclaw" \
.openclaw-cli/bin/openclaw --profile cascade-demo dashboard

This older path may open the default browser. It does not provide the newer dedicated-browser or Spark camera-discovery fixes.

Ask the operator for an approved update rather than pulling main during the event.[1][10][11]

Local Spark, laptop access and Brev are different paths

On the Spark, use 127.0.0.1. Spark does not provide Brev’s /guide/ or /openclaw/ routes.

A Tailscale address shared for another deployment is not a public link. For remote use, first arrange SSH access with the Spark’s operator. The stack must already be accepted and running.

Connect from your laptop

Replace user@spark-host below with your own Spark login and address. Run this on your laptop; keep this terminal open:

Laptop terminal · replace the SSH login first
ssh -N -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:8091:127.0.0.1:8091 \
  -L 127.0.0.1:8092:127.0.0.1:8092 \
  -L 127.0.0.1:18790:127.0.0.1:18790 user@spark-host

Open http://127.0.0.1:8092 on the laptop for the PAAI WebUI. For native OpenClaw, use a second terminal to SSH into the Spark and run the dashboard command. Without a desktop session it prints the current sign-in link; open that link in your laptop browser. Do not share the link or its token.

Install the camera extension in the laptop browser

  1. Copy extensions/chrome from the same installed revision on the Spark. You only need that directory, not another simulator, model or OpenClaw installation.
  2. In Chrome or Chromium, open chrome://extensions, enable Developer mode, click Load unpacked and select the copied folder containing manifest.json.
  3. Open the connected native OpenClaw tab. Click the PAAI extension or press Ctrl + Shift + Y (Command + Shift + Y on macOS).
  4. Choose Connect cameras and allow access to the forwarded local host. Select Side panel or Show in chat.
  5. Check that Kitchen, Worktop and Side all advance. If not, use Reconnect and camera recovery. A working chat alone is not camera acceptance.

Optional copy template, run on the laptop. Replace the login and, for a custom installation, the remote paai-spark folder. Use a new local destination folder:

Laptop terminal · replace remote login and folder first
test ! -e "$HOME/paai-camera-extension" && \
scp -r user@spark-host:paai-spark/extensions/chrome "$HOME/paai-camera-extension"

Manual Load unpacked works independently of Chromium’s automatic launcher flag. On the Spark’s supported desktop path, the launcher loads the extension for you; do not repeat this manual setup there.[4][11]

Ports to keep private

  • 8080: local Qwen API.
  • 8091: cameras; 8092: local WebUI.
  • 8611: Isaac bridge.
  • 18790: demo OpenClaw gateway. Your personal 18789 gateway stays separate.
  • 8093 and 4043: optional visitor surface and dedicated ngrok agent API.

On the Spark, ss -ltnp shows listeners before launch. Resolve conflicts without killing unrelated services. The SSH command binds forwarded ports to laptop loopback only. Never forward raw backend ports to the public internet; use the authenticated visitor option for a shareable URL.[2]

Optional: install and enable authenticated ngrok access

This is a separate testing option, not required for the local event demo. Rehearse the normal Spark path first.

  1. Install the Linux arm64 executable from ngrok’s official download page. Use your own account and a stable domain.
  2. Save the ngrok token in a private ngrok configuration file. In a text editor, create a separate visitor-auth JSON file outside the repository containing {"username":"<visitor-name>","password":"<visitor-password>"}. Choose a password of at least 12 characters.
  3. Set both private files to mode 0600 (owner read/write only). Never put credentials in URLs, shell commands, chat or commits. Replace every placeholder in the enable command with your actual paths and domain.
  4. On the Spark, check loginctl show-user "$USER" -p Linger. It must report Linger=yes to survive logout. Otherwise ask the administrator to enable linger.

Enable the dedicated services

Spark terminal · replace placeholders before use
python3 "${PAAI_INSTALL_DIR:-$HOME/paai-spark}/scripts/spark_public.py" enable --repo "${PAAI_INSTALL_DIR:-$HOME/paai-spark}" --domain '<your-domain>.ngrok.dev' --auth-file '<private-visitor-auth.json>' --ngrok '<path-to-ngrok>' --ngrok-config '<existing-ngrok.yml>'

Check PUBLIC ENABLED means registered, not yet ready. A stopped demo still needs its normal startup and proof.

Check after the demo reaches READY

Spark terminal · read-only public readiness check
python3 "${PAAI_INSTALL_DIR:-$HOME/paai-spark}/scripts/spark_public.py" check --repo "${PAAI_INSTALL_DIR:-$HOME/paai-spark}"

Check PUBLIC READY. Authenticated visitors get cameras and the restricted demo chat, not native OpenClaw administration.

Disable public access when finished

Spark terminal · stops the public services and their demo
python3 "${PAAI_INSTALL_DIR:-$HOME/paai-spark}/scripts/spark_public.py" disable --repo "${PAAI_INSTALL_DIR:-$HOME/paai-spark}"

Check PUBLIC STOPPED. This stops the dedicated public services and their demo stack, but keeps the installation files.

The supervised demo has bounded crash recovery, not an unlimited restart loop. A launch that never reaches READY needs diagnosis. Never expose the gateway, model API, Isaac bridge or MCP ports directly.[2]

End the session: stop and verify only this checkout’s stack

Wait for the last order to finish. Run:

Spark terminal · clean stop and ownership check
bash -e <<'BASH'
cd "${PAAI_INSTALL_DIR:-$HOME/paai-spark}"
./run.sh down
remaining=$(./run.sh down --dry-run)
printf '%s\n' "$remaining"
case "$remaining" in *'would stop'*) exit 1 ;; esac
printf 'STOPPED\n'
BASH

Check STOPPED, with no would stop lines. Installed files remain; the next cold launch will run its startup proof again.

Rehearse before calling the setup accepted

Use the actual Spark and intended interface:

  1. Start native OpenClaw with all three cameras live.
  2. Place the green cube inside its square, then reset.
  3. Place the orange inside the box, then reset.
  4. Recover from a deliberate service restart using the agreed procedure.
  5. Repeat with the exact GUI/headless setting and local edits that will ship.

These are acceptance requirements, not results claimed by this guide.

If it still fails Send one diagnostic bundle: installed revision, exact action, first error, log path and local changes. Include the cleanup script if used. Remove passwords, authentication links and tokens before sharing logs.
